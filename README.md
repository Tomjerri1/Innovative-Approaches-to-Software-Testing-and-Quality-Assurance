# Код-рев'ю

## Main.java

1. **Рядок 1** - порожній рядок на початку файлу.
2. **Рядки 2–8** - шапка оформлена як `/* */`, а не Javadoc `/** */`, тому IDE та `javadoc` її не розпізнають.
3. **Рядок 3** - `@author george` - у шапці вказано системний логін, а не справжнє ім'я автора.
4. **Рядок 4** - `@project Default (Template) Project` - назва проєкту шаблонна, а не `Triangle`.
5. **Рядок 5** - `@class ${NAME}` - змінна шаблону не підставилась.
6. **Рядок 6** - `@version 1.0.0` має зайвий пробіл у кінці рядка (trailing whitespace).
7. **Рядок 7** - `@since 05/09/2026 - 20.16` - неоднозначний формат дати (дд/мм чи мм/дд), нестандартний запис часу через крапку.
8. **Рядки 10–11, 13–14, 18–19** - залишені підказки `//TIP ...` від шаблону IntelliJ; це шум, який не стосується проєкту.
9. **Рядок 12** - `void main()` без оголошення класу (unnamed class / instance main). Це працює лише на JDK 25 і ускладнює розуміння, до якого класу належить код.
10. **Рядок 12** - відсутній `package`; клас у default package неможливо імпортувати з іншого пакета.
11. **Рядок 15** - `String.format("Hello and welcome!")` без аргументів - зайвий виклик, достатньо рядкового літерала.
12. **Рядок 15** - привітання "Hello and welcome!" - демо-код шаблону, не пов'язаний із предметною областю.
13. **Рядки 17–21** - цикл друкує `i = 1..5` - безглуздий демонстраційний код, що не має відношення до трикутників.
14. **Рядок 17** - магічне число `5` без імені константи.
15. **Весь файл** - `Main` не створює і не використовує `Triangle`: програма нічого не демонструє.
16. **Весь файл** - немає введення даних користувачем (сторін трикутника) ні з консолі, ні з аргументів.
17. **Весь файл** - відсутня обробка помилок (некоректні дані, `NumberFormatException`).

## Triangle.java

18. **Рядок 1** - порожній рядок на початку файлу.
19. **Рядок 2** - відсутній `package`.
20. **Рядок 2** - немає Javadoc до класу: незрозуміло призначення, одиниці виміру, інваріанти.
21. **Рядок 2** - клас не `final`, проте `equals` оголошений `final` - непослідовність; або клас `final`, або `equals` без `final`.
22. **Рядки 3–5** - поля `a`, `b`, `c` мають неінформативні імена; краще `sideA`, `sideB`, `sideC`.
23. **Рядки 3–5** - поля не `final`, клас змінюваний, хоча значення беруть участь у `hashCode()`. Якщо змінити сторону після додавання у `HashSet`/`HashMap`, об'єкт «загубиться».
24. **Рядки 7–29** - методи `takeA/putA` порушують конвенцію JavaBeans (`getA/setA`); багато інструментів і фреймворків їх не побачать.
25. **Рядки 11, 19, 27** - сеттери не валідують значення: можна записати від'ємне число, нуль, `NaN`, `Infinity`.
26. **Рядки 7–29** - шість тривіальних методів доступу засмічують клас; для незмінного значення краще `record`.
27. **Рядок 31** - конструктор не перевіряє, що сторони додатні.
28. **Рядок 31** - конструктор не перевіряє нерівність трикутника (`a + b > c` тощо): можна створити неіснуючий трикутник, наприклад `1, 1, 10`.
29. **Рядок 31** - конструктор не відхиляє `NaN` та `Infinity`.
30. **Рядки 37–38** - порожній конструктор за замовчуванням створює «трикутник» 0, 0, 0 - невалідний об'єкт.
31. **Рядки 31–38** - конструктори розташовані після методів доступу; за конвенціями порядок: поля → конструктори → методи.
32. **Рядки 40–53** - відступи в 3 пробіли замість 4 (решта файлу використовує 4); це порушує і Google Style, і Sun Checks.
33. **Рядок 40** - назва `perim` - скорочення; має бути `perimeter` / `getPerimeter`.
34. **Рядок 44** - назва `area` не відображає дію; прийнято `getArea` або `calculateArea`.
35. **Рядок 45** - `perim()` викликається чотири рази в одному виразі: зайві обчислення, дублювання.
36. **Рядок 45** - число `0.5` повторюється чотири рази (магічне число); потрібна локальна змінна `semiPerimeter`.
37. **Рядок 45** - вираз у один рядок із довгим ланцюжком множень важко читати; потрібна розбивка на кроки.
38. **Рядок 45** - відсутні пробіли навколо операторів (`0.5*perim()-a`) - порушення стилю.
39. **Рядок 45** - для неіснуючого трикутника `Math.sqrt` від'ємного числа повертає `NaN` мовчки, без помилки.
40. **Рядок 45** - формула Герона чисельно нестабільна для дуже «голкоподібних» трикутників; варто використати варіант Кахана з відсортованими сторонами.
41. **Рядок 48** - подвійні пробіли в `public  boolean  equilateral(){` та відсутній пробіл перед `{`.
42. **Рядок 48** - булевий метод має називатися `isEquilateral()`.
43. **Рядки 49–51** - `if (...) { return true; } else return false;` - надлишкова конструкція, достатньо `return a == b && b == c;`.
44. **Рядок 51** - `else return false;` без фігурних дужок і в одному рядку з `}` - суперечить Google Style.
45. **Рядок 52** - зайвий порожній рядок перед закривальною дужкою методу.
46. **Рядок 49** - порівняння `double` через `==` небезпечне через похибки округлення; при цьому `equals` використовує `Double.compare` - підходи непослідовні.
47. **Рядки 40–53** - реалізовано лише рівносторонній тип; немає рівнобедреного, прямокутного, різностороннього - функціональність неповна.
48. **Рядки 64–69** - `equals` вважає трикутники `(3, 4, 5)` і `(5, 4, 3)` різними, хоча вони рівні (конгруентні); порядок сторін не повинен впливати на рівність, або це треба явно задокументувати.
49. **Рядки 64–69** - немає швидкої перевірки `this == o`.
50. **Рядок 68** - довгий рядок (понад 100 символів) із трьома порівняннями - порушення ліміту довжини рядка Google Style.
51. **Рядки 55–62** - `toString` будує рядок конкатенацією; можна `String.format`, а для `record` метод генерується автоматично.
52. **Весь файл** - відсутні Javadoc-коментарі до публічних методів.

## Project structure and infrastructure

53. **Весь проєкт** - немає жодного юніт-тесту (немає `test/`, немає JUnit); коректність `area()`, `perim()`, `equilateral()` не перевірена.
54. **Весь проєкт** - відсутній збирач (Maven/Gradle): проєкт неможливо зібрати з командного рядка і в CI, лише через IntelliJ.
55. **`.idea/`** - папка IDE закомічена в репозиторій (`misc.xml`, `modules.xml`, `vcs.xml`, `checkstyle-idea.xml`, `google-java-format.xml`) - вона містить локальні налаштування.
56. **`Triangle.iml`** - файл модуля IDE також у репозиторії.
57. **`.gitignore`** - не містить `.idea/` та `*.iml`.
58. **`.gitignore`** - не містить `*.class`.
59. **`.gitignore`** - містить зайві правила для Eclipse, NetBeans, VS Code, Kotlin (`.kotlin`), яких у проєкті немає.
60. **`.idea/misc.xml`** - жорстко задано `corretto-25`; без збирача версія JDK ніде більше не зафіксована.
61. **`.idea/checkstyle-idea.xml`** - підключено одразу Sun Checks і Google Checks; їхні вимоги суперечать одна одній (наприклад, відступи 4 проти 2 пробілів).
