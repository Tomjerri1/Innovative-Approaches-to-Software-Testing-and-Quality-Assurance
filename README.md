# Код-рев'ю

## Main.java

1. - порожній рядок на початку файлу.
2. - шапка оформлена як `/* */`, а не Javadoc `/** */`, тому IDE та `javadoc` її не розпізнають.
3. - `@author george` - у шапці вказано системний логін, а не справжнє ім'я автора.
4. - `@project Default (Template) Project` - назва проєкту шаблонна, а не `Triangle`.
5. - `@class ${NAME}` - змінна шаблону не підставилась.
6. - `@version 1.0.0` має зайвий пробіл у кінці рядка (trailing whitespace).
7. - `@since 05/09/2026 - 20.16` - неоднозначний формат дати (дд/мм чи мм/дд), нестандартний запис часу через крапку.
8. - залишені підказки `//TIP ...` від шаблону IntelliJ; це шум, який не стосується проєкту.
9. - `void main()` без оголошення класу (unnamed class / instance main). Це працює лише на JDK 25 і ускладнює розуміння, до якого класу належить код.
10. - відсутній `package`; клас у default package неможливо імпортувати з іншого пакета.
11. - `String.format("Hello and welcome!")` без аргументів - зайвий виклик, достатньо рядкового літерала.
12. - привітання "Hello and welcome!" - демо-код шаблону, не пов'язаний із предметною областю.
13. - цикл друкує `i = 1..5` - безглуздий демонстраційний код, що не має відношення до трикутників.
14. - магічне число `5` без імені константи.
15. - `Main` не створює і не використовує `Triangle`: програма нічого не демонструє.
16. - немає введення даних користувачем (сторін трикутника) ні з консолі, ні з аргументів.
17. - відсутня обробка помилок (некоректні дані, `NumberFormatException`).

## Triangle.java

18. - порожній рядок на початку файлу.
19. - відсутній `package`.
20. - немає Javadoc до класу: незрозуміло призначення, одиниці виміру, інваріанти.
21. - клас не `final`, проте `equals` оголошений `final` - непослідовність; або клас `final`, або `equals` без `final`.
22. - поля `a`, `b`, `c` мають неінформативні імена; краще `sideA`, `sideB`, `sideC`.
23. - поля не `final`, клас змінюваний, хоча значення беруть участь у `hashCode()`. Якщо змінити сторону після додавання у `HashSet`/`HashMap`, об'єкт «загубиться».
24. - методи `takeA/putA` порушують конвенцію JavaBeans (`getA/setA`); багато інструментів і фреймворків їх не побачать.
25. - сеттери не валідують значення: можна записати від'ємне число, нуль, `NaN`, `Infinity`.
26. - шість тривіальних методів доступу засмічують клас; для незмінного значення краще `record`.
27. - конструктор не перевіряє, що сторони додатні.
28. - конструктор не перевіряє нерівність трикутника (`a + b > c` тощо): можна створити неіснуючий трикутник, наприклад `1, 1, 10`.
29. - конструктор не відхиляє `NaN` та `Infinity`.
30. - порожній конструктор за замовчуванням створює «трикутник» 0, 0, 0 - невалідний об'єкт.
31. - конструктори розташовані після методів доступу; за конвенціями порядок: поля → конструктори → методи.
32. - відступи в 3 пробіли замість 4 (решта файлу використовує 4); це порушує і Google Style, і Sun Checks.
33. - назва `perim` - скорочення; має бути `perimeter` / `getPerimeter`.
34. - назва `area` не відображає дію; прийнято `getArea` або `calculateArea`.
35. - `perim()` викликається чотири рази в одному виразі: зайві обчислення, дублювання.
36. - число `0.5` повторюється чотири рази (магічне число); потрібна локальна змінна `semiPerimeter`.
37. - вираз у один рядок із довгим ланцюжком множень важко читати; потрібна розбивка на кроки.
38. - відсутні пробіли навколо операторів (`0.5*perim()-a`) - порушення стилю.
39. - для неіснуючого трикутника `Math.sqrt` від'ємного числа повертає `NaN` мовчки, без помилки.
40. - формула Герона чисельно нестабільна для дуже «голкоподібних» трикутників; варто використати варіант Кахана з відсортованими сторонами.
41. - подвійні пробіли в `public  boolean  equilateral(){` та відсутній пробіл перед `{`.
42. - булевий метод має називатися `isEquilateral()`.
43. - `if (...) { return true; } else return false;` - надлишкова конструкція, достатньо `return a == b && b == c;`.
44. - `else return false;` без фігурних дужок і в одному рядку з `}` - суперечить Google Style.
45. - зайвий порожній рядок перед закривальною дужкою методу.
46. - порівняння `double` через `==` небезпечне через похибки округлення; при цьому `equals` використовує `Double.compare` - підходи непослідовні.
47. - реалізовано лише рівносторонній тип; немає рівнобедреного, прямокутного, різностороннього - функціональність неповна.
48. - `equals` вважає трикутники `(3, 4, 5)` і `(5, 4, 3)` різними, хоча вони рівні (конгруентні); порядок сторін не повинен впливати на рівність, або це треба явно задокументувати.
49. - немає швидкої перевірки `this == o`.
50. - довгий рядок (понад 100 символів) із трьома порівняннями - порушення ліміту довжини рядка Google Style.
51. - `toString` будує рядок конкатенацією; можна `String.format`, а для `record` метод генерується автоматично.
