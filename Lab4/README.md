1. **Робота з байтами замість `String`:** Файл читається одним викликом `readAllBytes()` у масив байтів. Слова не копіюються в окремі об'єкти - зберігаються лише їхні зсуви та довжина у вихідному масиві.
2. **Швидкий парсинг і хешування за 1 прохід:** Замість регулярних виразів та умовних перевірок використовується таблиця `LOWER[256]` для миттєвого приведення до нижнього регістру та пошуку роздільників одночасно з обчисленням хешу.
3. **Власна хеш-таблиця на примітивах (`FastWordCounter`):** Замість `HashMap<String, Integer>` використано open-addressing таблицю на єдиному масиві `int[]` (чергуються хеш, зсув, довжина, лічильник) на 16 384 слоти - без боксингу `Integer`, зайвих алокацій та `rehash`.
4. **Оптимізація холодного старту JVM:** Пошук топ-N слів реалізовано через компактний відсортований `int[]` (сортування вставкою). Із коду прибрано лямбди, `java.time` та конкатенацію рядків, щоб уникнути ініціалізації `invokedynamic` під час запуску.
